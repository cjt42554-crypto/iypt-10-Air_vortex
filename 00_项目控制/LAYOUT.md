# 仓库布局

```text
README.md
AGENTS.md
00_项目控制/
01_最终理论/
02_模拟程序/
03_项目资料/
90_候选工作区/
├── current/
└── archive/
tools/
.github/workflows/
```

## 目录职责

| 路径 | 职责 |
|---|---|
| `00_项目控制/` | 单一状态源、布局和工作流 |
| `01_最终理论/` | 已接受的理论成熟基线 |
| `02_模拟程序/` | 已接受的程序成熟基线 |
| `03_项目资料/` | 已接受的资料、协议、结果和归档 |
| `90_候选工作区/current/` | 当前候选、管理记录和审查材料 |
| `90_候选工作区/archive/` | 被替代候选归档 |

`01_最终理论` 表示当前成熟理论基线，不是不可修改的最终真理。

## 状态单一化

- 动态状态只写入 `STATUS.md`。
- 根 README 只导航。
- 当前候选 README 只描述候选自身。
- 冻结证据是不可变记录，不作为活动入口。

## 结构约束

- 每次任务从 `00_项目控制/README.md` 开始。
- 全仓库动态状态只以 `00_项目控制/STATUS.md` 为准。
- 新研究和修订默认写入 `90_候选工作区/current/`。
- 成熟基线只在用户明确指定范围并完成相应验证后回写。
- 当前候选入口固定为 `90_候选工作区/current/`，活动说明和命令不得指向其他候选入口。
- 冻结 acceptance、manifest 和日志不得为适配活动路径而改写。

机器检查由 `tools/check_repository_layout.py` 执行。
