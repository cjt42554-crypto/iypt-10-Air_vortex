# 工作流

## 1. 开始任务

1. 读取本目录 README 和 `STATUS.md`。
2. 涉及当前候选时读取 `90_候选工作区/current/README.md`。
3. 按任务需要读取管理、验证和历史材料。

## 2. 修改位置

- 新理论、程序修订、计划、验证和审查默认进入 `90_候选工作区/current/`。
- 根成熟基线用于稳定交付和比较。用户明确要求回写、热修复或结构治理时，可以直接修改，但必须记录范围和验证结果。
- 用户的明确指令优先于仓库内一般约定。

## 3. 验证口径

必须区分结构检查、实现测试、数值资格、物理验证和成熟基线回写。历史 PASS 只对其绑定的文件、提交、配置和环境有效。

## 4. 回写与归档

1. 在 `管理/变更映射.md` 记录候选源和目标。
2. 执行风险匹配的测试并记录命令、环境、返回码和未执行项。
3. 按用户指定范围回写成熟基线。
4. 更新 `STATUS.md`。
5. 被替代候选移入 `90_候选工作区/archive/`。

## 5. 历史证据

冻结 acceptance、manifest 和日志中的路径不批量改写。所有仍需执行的 README、脚本和命令必须使用当前 v2 路径。

## 6. 版本控制

长期工作分支使用 `main`。不为获得整洁状态而无依据重置、覆盖或删除来源不明的内容。
