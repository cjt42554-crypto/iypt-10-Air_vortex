# HF3D 纯结构限界重构执行规划

## 1. 决策、授权与任务边界

当前正式模拟程序不存在需要推倒重写的整体架构失控，但 `02_模拟程序/src/airvortex/backends/high_fidelity_3d.py` 已同时承担单步推进、时间步控制、事务回滚、事件状态机、帧记录、诊断累计和结果组装，变更耦合已经偏高。Q1R4 将需要昂贵的整组三层重算，因此应在冻结和运行 Q1R4 之前完成一次严格限界的纯结构重构。

用户已于 2026-08-27 明确批准由 Codex 在本地完成本规划并推送远程 `main`。本次授权仅覆盖：

- `02_模拟程序/**`；
- 新建的 `90_候选工作区/current/02_HF3D纯结构限界重构/**`；
- 完成任务后更新 `90_候选工作区/交接说明_current.md` 与 `交接说明_history.md`。

本次不得修改：

- `01_最终理论/**`；
- `90_候选工作区/current/01_HF3D数值资格/**` 中已经冻结的 Q1、Q1R、Q1R2、Q1R3 配置、生成清单、报告、裁决器、补丁、证据身份和历史结果；
- 既有本地忽略归档及其登记哈希；
- 顶层 `AGENTS.md`，除非执行中发现其规则存在阻断本任务的自相矛盾，且不得自行改写授权边界。

不允许新建或使用其他分支。全部工作在本地 `main` 完成，全部验收门通过后再推送远程 `main`。本任务结束时不得自动冻结、启动或补跑 Q1R4。

## 2. 科学状态与非目标

Q1R3 已按冻结协议得到：

`Q1R3_SPATIAL_STAGE_FAIL_CLOSED__TEMPORAL_NOT_AUTHORIZED`

六个必需平滑量均未通过空间收敛门，时间收敛未评估，装置级预测仍为 `NO-GO`。本次重构不得改变、弱化或重新解释该结论。

本次重构不是以下任何事项：

1. 不是对 Q1R3 空间不收敛的数值修复；
2. 不是物理模型升级；
3. 不是提高预测精度的闭合修订；
4. 不是重新选择 Q1R4 网格、时间步、窗口或资源投入；
5. 不是删除旧兼容字段、旧输出别名或冻结历史脚本的清理工作；
6. 不是性能优化任务，除非某项结构抽取在保持执行顺序和数值结果完全不变的前提下自然消除纯 Python 管理开销。

若重构后 Q1R4 的结果发生改变，只能由后续重新冻结并真实运行的新算例证明；不得预先声称重构会改善收敛。

## 3. 必须冻结不变的行为契约

以下内容不得发生未经本规划明确允许的变化：

1. 连续方程、离散方程、局部闭合、边界条件和算子执行顺序；
2. 数组 dtype、网格布局、掩膜语义和 CPU/CUDA 浮点归约路径；
3. 时间步上限公式、limiter 选择、CFL 控制目标、硬门、回滚和重试语义；
4. 压力投影器的构造、历史检查点、恢复、显式 CPU/CUDA 选择和 fail-closed 行为；
5. 配置 schema、字段名称、默认值、验证规则和未知字段拒绝行为；
6. `HighFidelityBackend` 的 backend ID、display name、capabilities 和 limitations；
7. 现有公开及仓库内部实际使用的 Python 导入路径；
8. `SimulationResult` 的 status、times、observables、fields、events、units、metadata 和数组形状；
9. 兼容输出别名及其精确等价关系，包括但不限于：
   - `surface_depth` 与 `surface_depth_m`；
   - `min_gap_to_bar` 与 `min_gap_to_bar_m`；
   - `actual_bar_rpm` 与 `equivalent_bar_rpm`；
   - `liquid_volume_error` 与 `liquid_mass_error_relative` 的现有归档数值关系；
10. soft stop、进度回调、实时只读预览和输出对齐行为；
11. 所有数值质量门、阈值、异常类型和机器可读失败载荷。

允许变化仅限于：

- 模块路径和内部类的组织；
- 为保持旧导入路径而增加的显式 re-export；
- 新增 characterization tests、等价性比较器和结构说明；
- 源码树哈希、Git commit、运行时间戳和墙钟耗时等必然随提交或执行变化的身份字段。

## 4. 目标架构

保留以下正式公开入口：

`02_模拟程序/src/airvortex/backends/high_fidelity_3d.py`

该文件继续提供现有可见符号和 `HighFidelityBackend`，但不再直接承载全部实现。先用仓库范围搜索枚举当前所有导入和测试依赖，再通过显式 re-export 保持兼容。

建议新建内部包：

`02_模拟程序/src/airvortex/hf3d/`

模块职责原则如下。实际文件名可在不破坏职责边界的前提下小幅调整，但不得重新形成新的单体模块。

### 4.1 `types.py`

承载：

- `HF3DState`；
- `HF3DStepDiagnostics`；
- `HF3DRejectedStepDiagnostics`；
- `HF3DPostProjectionCFLExceeded`；
- 时间步 limiter 的稳定名称、编码和有类型的数据结构；
- 仅保存状态与数据合同，不放求解流程。

### 4.2 `drive.py`

承载：

- rpm 与角速度转换；
- 分段线性实际转速及右侧斜率；
- 配置转速历程的角度精确积分。

必须保持现有端点、符号、插值和右导数语义。

### 4.3 `pressure.py`

承载：

- CPU/CUDA 投影器构造；
- GPU availability probe；
- `auto`、`cpu`、`cuda` 选择；
- 构造失败、运行时失败和禁止静默回退的现有语义。

不得改变投影算子、容差、迭代上限或设备间传输方式。

### 4.4 `timestep.py`

承载：

- 已知状态下的全部时间步上限；
- limiter 选择；
- 联合源项正根；
- post-projection CFL retry 的新步长计算；
- 有类型的 `TimeStepProposal` 或等价结构。

不得继续以 `dict[str, float | str]` 作为内部主合同。对外诊断所需名称和数值仍须原样输出。

### 4.5 `stepper.py`

承载单个 trial step：

1. 相输运；
2. 界面压缩；
3. 密度和黏度更新；
4. 动量输运；
5. 黏性项；
6. 表面张力；
7. 浸没边界松弛；
8. 旋转系体力和重力；
9. 压力投影；
10. CFL、压力残差和有限性门；
11. 全部门通过后的状态提交。

必须保持当前操作顺序。trial 失败时只允许恢复投影历史并抛出既有语义的异常；不得提前改变 `HF3DState`。

### 4.6 `events.py`

承载拓扑事件状态机：

- `gas_touches_bar`；
- `resolved_channel`；
- `channel_reconnect`；
- `channel_break`；
- `sustained_channel_numerical`。

事件名称、触发时刻、触发条件、重复抑制和 payload 必须保持一致。

### 4.7 `recording.py`

承载：

- `FrameRecorder` 或等价帧记录器；
- `StepDiagnosticsBuffer` 或等价逐步诊断缓冲；
- observable、field、unit 和 alias 的集中登记；
- 最终 `SimulationResult` 组装；
- 最终三维场和轴对称平均帧的归档。

主循环不得继续手工维护几十个相互平行的列表，并在多个位置分别同步字段。兼容别名必须由一个显式、受测试的 alias 映射生成，而不是散落重复追加。

### 4.8 `high_fidelity_3d.py` 的最终职责

最终文件只负责：

- 保持公开兼容入口；
- 配置验证和网格构造；
- 建立 projection、state、recorder、event tracker；
- 驱动时间循环、Control 和 Progress；
- 调用 timestep、stepper、events 和 recording；
- 返回最终结果。

不要为了压缩行数创建大量一行包装函数。判断是否完成的核心标准是状态所有权和职责是否清晰，而不是机械行数指标。

## 5. 执行阶段

### 阶段 A：建立重构前基线

修改正式源码前必须：

1. 确认本地 `main` 与远程 `main` 同步，工作树干净；
2. 记录当前 HEAD 和正式源码树 SHA-256；
3. 执行并记录：
   - 正式程序完整测试；
   - 正式 self-check；
   - `compileall`；
   - `90_候选工作区/current/01_HF3D数值资格/tests` 的候选测试；
4. 在新目录 `90_候选工作区/current/02_HF3D纯结构限界重构/` 保存基线报告，不覆盖旧资格证据；
5. 选择或新建一个候选区专用、计算成本较低但能覆盖非零转速、输出对齐、帧记录和完整结果组装的 CPU 固定配置；该配置不承载科学结论；
6. 在 CUDA 可用时增加一个固定 CUDA 短重放；无 CUDA 时明确记录未执行，禁止伪造通过；
7. 保存重构前的：
   - times；
   - status；
   - events；
   - observable 和 field 的键、shape、dtype、数组值；
   - units；
   - 数值相关 metadata；
   - 每步诊断数组；
   - 最终完整三维场；
8. 对 CFL rejected trial、projection history restore、soft stop 和非零初始转速等难以由一个完整短算例覆盖的行为，先补 characterization tests。

如果当前基线测试本身失败，不得开始重构。先在新候选目录记录失败事实并停止，不能把既有失败混入重构提交。

### 阶段 B：先抽取纯数据和纯辅助逻辑

依次抽取 `types.py`、`drive.py`、`pressure.py`。每次抽取后：

- 保留旧导入路径；
- 运行受影响测试；
- 不改变任何运算表达式；
- 不顺手改名、格式化大段无关代码或修复未证实问题。

### 阶段 C：抽取时间步与事务式单步推进

抽取 `timestep.py` 和 `stepper.py`。这一阶段风险最高，必须增加或保留以下门：

1. rejected trial 后 state 的时间、步数、角度和全部数组逐元素不变；
2. rejected trial 后 CPU projection history 恢复；
3. CUDA 可用时 projection history 同样恢复；
4. retry 接受步的 limiter、retry count、最大拒绝 CFL 和全部诊断与基线一致；
5. `output_alignment`、`registered_time_step`、`combined_known_source_cfl`、`viscous_stability`、`capillary_stability`、`rotation_increment` 和 `post_projection_cfl_retry` 的身份保持一致；
6. retry 耗尽异常的 JSON payload 结构和键保持一致。

### 阶段 D：抽取事件和记录系统

抽取 `events.py` 与 `recording.py`，消除主循环的平行列表和分散 alias 构造。必须验证：

- 所有 output key 集合完全一致；
- key 顺序仅在下游明确不依赖时允许变化，优先保持现有顺序；
- alias 数组逐元素相同；
- units 与 observables 一一对应；
- event 序列及 payload 完全一致；
- 实时预览只读，不影响求解状态；
- soft stop 的终态、status 和事件不变。

### 阶段 E：清理单体入口并完成集成

完成后：

- 不得同时保留旧、新两套活动 stepper、recorder 或 event tracker；
- 不得通过运行时 import fallback、monkey patch 或环境开关选择旧实现；
- 可保留的只有兼容 re-export，不得复制核心算法；
- 删除或移动内部符号前，必须用仓库范围搜索修复全部活动引用；
- 不触碰冻结 Q1R3 裁决器和历史补丁。

## 7. 严格数值等价性验收

重构完成后，使用阶段 A 的相同环境、配置和命令重新运行。

### 7.1 必须完全一致的内容

对 CPU 固定基线，以下内容原则上必须使用 `np.array_equal` 或结构完全相等：

- times；
- status；
- events；
- 所有 observables；
- 所有 fields；
- shapes 和 dtypes；
- units；
- limiter code、retry count、CFL、散度、压力残差、迭代数和逐算子加速度；
- 最终三维场和拓扑掩膜；
- 除明确白名单外的 metadata。

CUDA 在同一硬件、驱动、CuPy、NumPy 和 SciPy 环境中也优先要求逐元素一致。若不一致，必须定位首个差异步和首个差异字段；不得自行改为宽松容差后通过。

### 7.2 允许不同的字段白名单

仅允许预先明确登记的身份或非确定性运行字段不同，例如：

- Git commit；
- 正式源码树 SHA-256；
- 运行时间戳；
- 墙钟耗时。

白名单必须逐项列在等价性报告中。不得用“metadata 不比较”作为整体豁免。

### 7.3 失败处理

出现任何非白名单差异时：

1. 停止后续结构移动；
2. 定位首个差异提交、时间步和字段；
3. 修正或回退造成差异的重构；
4. 重新执行完整基线；
5. 不得降低测试阈值、数值门或比较标准。

在严格等价性未通过前不得推送最终重构。
