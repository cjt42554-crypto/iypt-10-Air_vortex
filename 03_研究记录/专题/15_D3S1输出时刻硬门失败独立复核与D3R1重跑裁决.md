## 2. 冻结失败是否成立

### 2.1 合同语义

D3 V1 冻结：

```text
native_output_times_s =
[0.000, 0.001, 0.002, 0.003, 0.004, 0.005,
 0.006, 0.007, 0.008, 0.009, 0.010]
```

并明确要求：

```text
六个算例原生输出时间逐位等于 native_output_times_s
interpolation = PROHIBITED
任一完成性、CUDA、数值质量或证据硬门失败
→ D3_INCONCLUSIVE_FAIL_CLOSED
```

因此，只要归档时间数组有一个元素不逐位相等，V1 就必须失败。不能在看到失败后把“逐位相等”解释成容差相等。

### 2.2 实现递推

执行提交中的候选运行器使用：

```python
next_output = min(output_interval, end_time)
...
runtime.state.time_s = next_output
runtime.recorder.record_frame(...)
...
next_output += output_interval
```

正式 `FrameRecorder.record_frame()` 随后直接执行：

```python
self.times.append(state.time_s)
```

因此，第 $k$ 个登记时刻的位模式来自对二进制浮点 `0.001` 的重复累加，而不是直接来自冻结向量的第 $k$ 个元素。

### 2.3 独立 IEEE-754 复算

冻结字面量 `0.009` 的双精度表示为：

```text
float.hex = 0x1.26e978d4fdf3bp-7
uint64    = 4576341768551784251
```

从 `0.001` 开始重复累加八次得到：

```text
0.009000000000000001
float.hex = 0x1.26e978d4fdf3cp-7
uint64    = 4576341768551784252
```

两者恰为相邻浮点数：

```text
delta = 1.734723475976807e-18 s
ULP distance = 1
nextafter(0.009, +inf) = 0.009000000000000001
```

运行器在最终时刻又把 `state.time_s` 单独钳到 `end_time = 0.01`，所以该实现会在索引 9 产生唯一的逐位差异，而索引 10 恢复为冻结的 `0.01`。这与 current 所记录的失败形态完全一致。

### 2.4 裁决

```text
D3_V1_S1_FAIL_CLOSED = UPHELD
```

V1 硬门按合同正确工作。不能追认 G6_DT0 为 PASS，不能删除失败标记，不能继续 G6_DT1/G6_DT2，也不能让 S2 或 S3绕过已提交的 `FAILED_STOPPED`。

## 3. 失败性质

该失败不是以下任一种：

```text
NOT_A_PHYSICAL_MODEL_FAILURE
NOT_A_CUDA_FALLBACK
NOT_A_SOLVER_DIVERGENCE
NOT_A_PRESSURE_OR_CFL_GATE_FAILURE
NOT_A_FORMAL_SOURCE_DRIFT
NOT_A_SCIENTIFIC_CLASSIFICATION
```

它是：

```text
CANDIDATE_OUTPUT_SCHEDULE_FLOAT_ACCUMULATION_DEFECT
```

合同把冻结向量定义为唯一时刻身份，运行器却用另一种浮点生成算法构造时刻。二者在 `0.009 s` 不同一位，因此合同和实现内部不一致。

current 记录的其他质量门通过，只能说明该完整 G6_DT0 在所记录环境中没有触发那些门；它不改变 V1 的失败，也不能形成 D3 分类。由于网页端无法访问 ignored raw，本轮不独立认证这些其他质量值。

## 4. 拒绝的处置方式

以下方式全部拒绝：

1. 把 V1 的 `native_output_times_exact` 改成容差门后追认旧运行；
2. 把冻结向量的 `0.009` 改成 `0.009000000000000001`；
3. 只改 case summary 或 stage ledger，把 G6_DT0 手工写成 PASS；
4. 复用 G6_DT0 的 `partial.npz`，只补跑剩余五个算例；
5. 从失败 S1 继续 G6_DT1、G6_DT2、S2 或 S3；
6. 删除、移动或覆盖 V1 ignored raw 后在原路径重跑；
7. 修改正式 `02_模拟程序/**` 的 `FrameRecorder` 来迎合候选协议；
8. 使用旧允许态授权对象重新启动 V1。

即使 1 ULP 对物理结果可以忽略，旧运行仍不满足预注册的证据身份。后验放宽门或重标时刻会破坏可审计性。

## 8. 输出调度实现要求

运行器不得再使用：

```python
next_output += output_interval
```

必须由合同的冻结向量直接驱动：

```text
registered_times = exact float64 parsing of native_output_times_s
next_index starts at 1
next_target = registered_times[next_index]
advance only to next_target
when reached within the existing alignment tolerance:
    state.time_s = registered_times[next_index]
    record exactly one frame
    next_index += 1
```

同时要求：

1. `registered_times[0] == 0.0`；
2. 严格单调且无重复；
3. 最后元素逐位等于 `run.duration_s`；
4. 配置的 `run.output_interval_s` 与登记向量相容，但不能作为累加生成源；
5. 不跳帧、不重复帧、不插值；
6. 完成后帧数和每个 uint64 位模式逐项等于冻结向量；
7. G6/G9 和 DT0/DT1/DT2 使用同一冻结向量身份；
8. 正式 `FrameRecorder` 保持只读，不在正式程序内增加 D3 特例。
