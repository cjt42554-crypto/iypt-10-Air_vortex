## 2. 根因裁决

原失败项为：

```text
authorization_file_is_only_change = false
```

人工提交差异显示，前一授权子提交从其受复核父提交到授权 HEAD 的唯一变化确为：

```text
90_候选工作区/current/07_D3跨网格时间步响应诊断/d3_execution_authorization.json
```

失败原因不是授权范围扩大、实现漂移、正式源码漂移或额外文件修改，而是 Git 默认 `core.quotePath=true` 时将含中文的路径输出成带引号的八进制转义串；旧审计随后把该文本与真实 Unicode 仓库相对路径直接比较，形成确定性的假阴性。

因此，前一失败裁决为：

```text
PREEXECUTION_MACHINE_GATE_FAIL_CLOSED
NOT_A_S0_FAILURE
NOT_A_NUMERICAL_FAILURE
NOT_A_DYNAMIC_EVIDENCE_RECORD
```

失败闭锁本身工作正常；需要修复的是授权审计的路径规范化，而不是放宽授权门。

## 3. 修复复核

### 3.1 路径读取修复：接受

运行器与独立分析器现在都通过同一语义的辅助函数读取提交差异：

```text
git -c core.quotePath=false diff --name-only <reviewed_commit> HEAD
```

该修复具有以下性质：

1. 配置只作用于本次 Git 命令，不修改用户级、仓库级或系统级 Git 配置；
2. 中文 UTF-8 路径以真实仓库相对路径返回，不再形成八进制转义文本；
3. 审计仍要求路径列表精确等于唯一授权文件，没有改成子串、后缀、集合包含或人工豁免；
4. `reviewed_commit` 仍必须是 40 位小写十六进制，命令参数不经 shell 展开；
5. 运行器和 S3 分析器的授权判据保持一致。

新零步静态证据中的旧授权审计已实际输出真实中文路径列表，其中包括本轮五个候选实现变更和旧授权文件；这同时证明：中文路径解码已正常，旧授权仍因父提交不匹配、实现绑定不匹配和非唯一授权变更而被正确拒绝。

### 3.2 授权生命周期回归：接受

测试和静态审计不再假设仓库中的授权对象必须永久保持默认拒绝，而是区分：

- 合法的显式拒绝对象；
- 形状合法但绑定已过期的允许态对象；
- 当前 HEAD 上父提交、唯一变更路径、实现 blob/hash、预注册、正式源码树和裁决文档全部精确匹配的允许态对象。

动态入口仍调用完整精确授权审计。显式拒绝、缺失或畸形授权、旧授权、实现漂移、父提交漂移、额外文件变化、预注册漂移和正式源码漂移仍在 raw 创建前失败闭锁。

这属于修复静态测试对授权生命周期的错误假设，不是降低授权强度。

### 3.3 非阻塞边界

当前辅助函数使用按行路径输出，而不是 NUL 分隔的任意字节路径协议。授权文件的冻结路径不含换行、制表符或前后空格，仅包含中文、ASCII、下划线、斜杠和点号；对当前精确路径而言，`core.quotePath=false` 足以消除已观察到的误判。为不存在的任意恶意文件名引入二进制路径解析，不是本次单用户科研工具的必要前置条件。
