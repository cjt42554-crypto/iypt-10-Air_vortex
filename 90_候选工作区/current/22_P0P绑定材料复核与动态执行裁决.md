6. 固定 18 项 schedule 的完整 canonical object 可重算为 `2138aea65041ff322a0cc2ce22945544d51d1e39db1929079f9f6265e494dceb`；
7. ticket 和 authorized grant 在材料生成时不存在，dynamic/P1 均为拒绝，执行计数全部为零；
8. 材料没有包含其自身所在 commit/tree 或未来 `P/C` commit 的自引用；

### 3.4 Git 拓扑

签名事务必须形成：

```text
I -> P -> C
```

其中：

- `P` 必须是 `I` 的单父子提交；
- `I..P` 只允许三个精确路径：
  - `90_候选工作区/current/17_HF3D性能优化/p0p_authorization_ticket.json`
  - `90_候选工作区/current/22_P0P绑定材料复核与动态执行裁决.md`
  - `90_候选工作区/交接说明_current.md`
- `P` 中授权文件仍必须是 denied blob；
- `C` 必须是 `P` 的单父子提交；
- `P..C` 必须且只能修改 `90_候选工作区/current/17_HF3D性能优化/p0p_execution_authorization.json`；
- 该路径必须从 denied regular blob 精确替换为上述 authorized regular blob；
- 禁止 rename、copy、symlink、submodule、第二路径或第二父提交。

`交接说明_history.md` 已在 `I` 中记录 Codex 的 review-material 交付。本签名事务不再改写 history，以把 `I..P` 缩减为三个可直接审计的精确路径；材料将 history 列为“仅在修改时允许”的可选路径，并不要求父票据必须修改它。本裁决文档承担本次追加审计记录。

## 4. 动态执行授权

当且仅当远端 `main` 指向合法的 `C`，本地满足：

```text

C has exactly one parent P

all ticket/blob/tree/path/mode/toolchain bindings pass

才授权一次固定 P0-P schedule。

本裁决只授权已冻结的 18 个样本，不授权：

任何旧 raw 复用
任何数值门、温度门、CFL、压力或散度阈值放宽
```

## 5. 本轮停止边界

本轮只签发 `P/C` 并推送 `C`，**不自动启动动态 campaign**。

后续本机执行前必须先进行非消费 preflight：

```bash
python3 90_候选工作区/current/17_HF3D性能优化/run_p0_performance_campaign.py --zero-step-preflight
```

只有 preflight 和随后的每样本环境门均通过时，才允许显式执行：

```bash
python3 90_候选工作区/current/17_HF3D性能优化/run_p0_performance_campaign.py --execute
```

执行前不得再产生任何提交或工作树修改；否则 `HEAD == origin/main == C` 和精确拓扑绑定失效。

若首次样本前环境门失败，应原样停止；preflight 不消费 claim。若 claim 后任何样本或环境门失败，必须提交失败证据并永久停止，禁止恢复或补跑。
