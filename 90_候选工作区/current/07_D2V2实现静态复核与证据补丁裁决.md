## 3. 开跑前必须修复的证据缺口

### P1. 零驱动事实必须由最终分析器失败闭锁

当前运行器会检查 `Z6/Z9` 的：

```text
actual_bar_rpm == 0
bar_angle_rad == 0
```

最终分析器虽然会重新计算，但未把该事实作为独立失败闭锁门。

要求：最终分析器必须直接从归档重算；任一输出点非零，则最终分析失败闭锁，不得生成 Z 的大小或方向分类。

至少增加失败测试：

- 单点转速非零；
- 单点磁子角度非零。

### P2. 锁步接受时间必须逐变体可独立重算

当前组摘要主要保存一条共同 `accepted_times_s` 和运行器给出的 `accepted_time_arrays_bitwise_equal`。

要求：对每个变体分别保存并进入跟踪证据：

```text
accepted_time_count
accepted_time_sha256
accepted_times_s
```

最终分析器必须从每个变体自己的记录重新编码为 `float64` 字节并逐位比较；不得把运行器布尔值作为最终证据。

至少增加失败测试：

- 某一变体最后一个接受时间改为 `nextafter` 后必须失败；
- 计数相同但字节不同必须失败。

### P3. 执行提交与正式 G0 必须独立绑定

要求最终分析器验证：

```text
git_revision_execution_start == execution_commit
git_revision_execution_end   == execution_commit
```

并对每个归档：

1. 从归档配置重新调用正式 `HighFidelityBackend.make_grid()`；
2. 将重建的正式 G0 `bar_mask` 与归档 `stir_bar_mask_3d` 逐元素比较；
3. 任一不一致则失败闭锁。

至少增加失败测试：

- 错误 execution commit；
- Git revision 边界与 execution commit 不一致；
- 归档 G0 掩膜翻转一个单元。
