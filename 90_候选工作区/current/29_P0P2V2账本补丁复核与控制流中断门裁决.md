## 2. 裁决 28 的普通存储异常问题已经关闭

本轮新增的 `_commit_ledger_transition()` 已经实现裁决 28 要求的核心提交判定：

1. `expected_before` 和 `candidate_after` 在写入前完整构造并深复制；
2. 写入前重新加载并要求磁盘 ledger 精确等于 `expected_before`；
3. 每次发布尝试之后严格重载最终 ledger；
4. 观察到 `candidate_after` 时按已提交恢复；
5. 观察到精确 `expected_before` 时只使用同一候选重试一次；
6. 观察到第三种状态时失败闭锁；
7. 连续两次仍为旧状态时抛出 `LedgerTransitionNotCommitted`；
8. `RUNNING` 的 token、时间戳和 `start_count = 1` 在首次写入前只生成一次；
9. 普通 `PASS` 与最后一项 pending-terminal 共用相同语义；
10. outer handler 会重新加载持久 ledger，重建实际 PASS 前缀和唯一 RUNNING identity。

现有 OSError 故障矩阵证明：

```text
pre-commit once       -> 同一候选第二次提交
post-commit exception -> 识别候选已落盘并恢复
persistent pre-commit -> 不启动目标 worker/后续样本，并形成 FAILED_STOPPED
```

现有测试也直接核对了同一候选、唯一 token、无重复样本启动、`start_count = 1`、completion 与 failure 不共存，以及 durable RUNNING/PASS/pending-terminal 后 stale loop locals 不再决定终态。

因此，上一裁决针对普通可恢复存储异常的唯一阻断已经实质关闭。该主体实现可以保留，不需要复制 V3 harness，也不需要改变 contract、schedule、authorization、claim 或 raw namespace。

## 3. 阻塞一：统一 helper 错把控制流中断当作可重试存储故障

当前 `_commit_ledger_transition()` 对 `_publish_ledger(candidate)` 使用：

```python
except BaseException as exc:
    publication_errors.append(exc)
```

`BaseException` 不仅包含普通存储或序列化异常，还包含：

```text
KeyboardInterrupt
SystemExit
GeneratorExit
```

以及同类控制流终止信号。

这会产生两个不合法结果。

### 3.1 RUNNING 写入前收到用户中断，helper 仍可能提交并启动 worker

可构造顺序：

```text
mark_sample_running() 已冻结唯一 token/candidate
第一次 _publish_ledger() 在原子替换前收到 KeyboardInterrupt
helper 捕获并吞下 KeyboardInterrupt
严格重载仍观察到 expected_before
helper 使用同一 candidate 自动进行第二次发布
RUNNING 成功落盘并返回 token
execute_campaign() 随后启动 worker
```

结果是用户或上层控制器已经明确中断，程序却在中断之后新启动正式性能样本。这违反 fail-closed、单前台控制和“中断必须进入失败终态而不得继续后续工作”的既有设计。

### 3.2 RUNNING/PASS 已落盘后收到中断，中断会被静默转成成功返回

若 `KeyboardInterrupt` 或 `SystemExit` 发生在原子替换之后：

```text
_publish_ledger(candidate) 抛出控制流异常
helper 捕获异常
严格重载观察到 candidate_after
helper 返回成功
```

于是：

- durable RUNNING 后可能继续启动 worker；
- durable ordinary PASS 后可能继续下一项样本；
- durable final pending-terminal 后可能继续发布 completion；
- 原始中断没有传播给 campaign 的 `except BaseException`，无法登记中断失败。

当前测试只注入 `OSError`，没有 `KeyboardInterrupt` 或 `SystemExit` 负例，因而 `70/70` 不能覆盖这一控制流语义。

### 3.3 必须采用的语义

普通事务异常与控制流中断必须分层：

```text
ordinary Exception
  -> 允许按 durable ledger 分类，并在精确 old state 下用同一候选最多重试一次

KeyboardInterrupt / SystemExit / GeneratorExit / 其他非 Exception 的 BaseException
  -> 不得自动重试，不得被转换为正常返回，必须立即向外传播
```

控制流异常传播后，outer handler 再读取实际 ledger：

- 若仍为旧状态，形成全局 FAILED_STOPPED；
- 若已为 RUNNING，按精确 RUNNING identity 形成 FAILED_STOPPED；
- 若已为 PASS 或 pending-terminal，按实际 PASS 前缀形成全局 FAILED_STOPPED；
- 不得启动新 worker、下一样本或 completion。

最小实现通常是把 transition helper 的发布异常捕获从 `BaseException` 收窄为 `Exception`，并保留 outer campaign 对 `BaseException` 的终止事务处理。也可以使用更窄的明确 allowlist，但不得把线程环境、注释或测试 mock 本身当成行为证明。

## 4. 阻塞二：outer handler 仍先相信易过时的本地 `claimed` 布尔值

当前 `execute_campaign()` 的顺序是：

```python
claimed = False
create_claim_and_ledger(...)
claimed = True
```

而外层失败事务只有在以下条件下才运行：

```python
if claimed and no execution_failure and no execution_complete:
    _terminalize_consumed_claim_failure(...)
```

因此仍可构造：

```text
create_claim_and_ledger() 已经完整持久化 execution_claim.json
create_claim_and_ledger() 已经完整持久化并验证 schedule_ledger.json
函数返回边界前后收到 KeyboardInterrupt/SystemExit/OSError
调用方尚未执行 claimed = True
outer handler 观察 claimed == False
跳过 durable ledger 重载和失败终态化
```

最终留下：

```text
valid execution_claim.json
valid schedule_ledger.json = CLAIMED_NOT_STARTED
execution_complete.json absent
execution_failure.json absent
samples absent
```

该 claim 已经依法消费，下一次执行会因 raw 非空而拒绝，但本次又没有唯一合法终态。这正是本轮设计试图消除的悬空 consumed claim。

这个反例不要求极端磁盘损坏。测试 wrapper 只需调用真实 `create_claim_and_ledger()`，待其成功后立刻抛错，即可稳定复现“持久状态已提交而本地赋值尚未发生”的边界。

### 4.1 必须采用的语义

Outer handler 的权威条件必须是持久对象，而不是本地布尔值：

```text
valid claim + valid ledger + no valid completion/failure
  -> 必须终态化 consumed claim

no valid claim/ledger pair
  -> 不得伪造 claim consumption 或性能 failure
```

`claimed` 可以作为诊断字段，但不能作为是否执行终态化的前置授权。异常边界应尝试严格加载 claim/ledger；若二者形成合法绑定，就调用 `_terminalize_consumed_claim_failure()`，无论本地 `claimed` 是否已经赋值。

如果 `create_claim_and_ledger()` 已经自行发布了合法 initialization failure，则 outer handler应识别既有终态而不重复覆盖。
