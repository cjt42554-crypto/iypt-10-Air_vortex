# 按需参考：工作、验证与晋升规则

本文件在程序修复、数值/物理验证、实验比较、晋升或基线热修复时读取；简单查询、导航和不落盘分析无需读取。

## 普通工作流

1. 明确目标、允许写入范围、来源基线、成功条件和停止条件。
2. 默认只在 `未提交修改/当前任务/**` 修改，成熟目录只读。
3. 需要时更新变更映射、验收清单和修改记录；只处理本次任务对应条目。
4. 小步实现，按风险验证，并记录源码/提交身份、环境、命令、返回码、证据位置和未执行项。
5. 提交前检查差异范围、`git diff --check` 和三个成熟 tree。
6. 阶段成果直接在 `main` commit；需要接力时 push 到 `origin/main` 并记录实际结果。

## 最低验证证据

| 变更类型 | 最低要求 |
|---|---|
| 纯目录或文档整理 | 文件清单、相对链接、旧到新映射、Git diff、成熟 tree |
| 启动入口或路径调整 | 从规定入口执行帮助或自检，证明不依赖旧绝对路径 |
| 程序修复 | 直接相关测试、回归测试、失败反例、实际运行入口 |
| 数值或物理模型 | 单元/量纲/守恒、完整运行、几何与活动集、收敛/残差/不确定度 |
| 实验比较 | 预注册协议、校准/验证隔离、观测算子身份、原始数据来源、盲验证与不确定度 |

历史结果只能标为历史结果。源码、配置、环境或提交身份变化后，必须明确哪些项目已复验、哪些仍为 UNKNOWN、PARTIAL 或 NO-GO。

## Git 与证据

- 仓库只允许 `main`；不得创建、保留或 push 其他分支。
- 保留用户已有修改，不用重置或覆盖换取干净状态。
- commit/push 前重新运行仓库预检，并检查待推送提交和工作树。
- 不重写、删除或覆盖冻结机器证据；更正通过追加记录完成。
- 未实际成功 push 时，不得声称远端已更新。

## 晋升硬门

晋升不是普通开发步骤，必须同时满足：

1. 用户明确授权本次晋升及目标目录；
2. 候选范围冻结，来源基线和候选提交身份明确；
3. 变更映射逐项列出候选源、成熟目标、操作和理由；
4. 必需验收项全部通过，没有通过删测试、缩小采集或放宽阈值换取 PASS；
5. 当前候选身份对应的机器证据和人工审查结论齐全；
6. NO-GO、跳过项、外部依赖和残余风险已处理或由用户明确接受；
7. 晋升前记录成熟 tree 并保留可恢复提交；晋升后复验结构、链接、入口、测试和 tree；
8. 晋升只复制映射中获批内容，不复制缓存、临时结果或整个工作区；
9. 晋升使用 `main` 上独立可审查的 commit，并成功 push 到 `origin/main`。

候选工作区在晋升验收完成前不删除。

## 失败与回退

失败证据应保留并标为 FAIL、NO-GO、PARTIAL 或 UNKNOWN。回退必须绑定明确 commit 或 tree，优先用新提交恢复；除非用户明确要求，不重写 Git 历史。

成熟 tree 漂移、错误晋升或证据与源码身份不一致时，停止后续晋升，记录差异并请求用户决定。
