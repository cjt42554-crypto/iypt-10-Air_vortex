# 按需参考：工作、验证与晋升规则

本文件在程序修复、数值/物理验证、实验比较、晋升或基线热修复时读取；简单查询、导航和不落盘分析无需读取。

## 普通工作流

1. 明确目标、允许写入范围、来源基线、成功条件和停止条件。
2. 默认只在 `未提交修改/当前任务/**` 修改，成熟目录只读。
3. 需要时更新变更映射、验收清单和修改记录；只处理本次任务对应条目。
4. 小步实现，按风险验证，并记录被测文件和配置、环境、命令、返回码、证据位置及未执行项。
5. 交付前检查变更文件清单、相对链接和三个成熟目录，确认修改只落在授权范围。
6. 完成后保留修改和验证记录。

## 最低验证证据

| 变更类型 | 最低要求 |
|---|---|
| 纯目录或文档整理 | 文件清单、相对链接、旧到新映射、前后内容比较、成熟目录检查 |
| 启动入口或路径调整 | 从规定入口执行帮助或自检，证明不依赖旧绝对路径 |
| 程序修复 | 直接相关测试、回归测试、失败反例、实际运行入口 |
| 数值或物理模型 | 单元/量纲/守恒、完整运行、几何与活动集、收敛/残差/不确定度 |
| 实验比较 | 预注册协议、校准/验证隔离、观测算子身份、原始数据来源、盲验证与不确定度 |

历史结果只能标为历史结果。文件、配置或环境变化后，必须明确哪些项目已复验、哪些仍为 UNKNOWN、PARTIAL 或 NO-GO。

## 内容与证据保护

- 保留用户已有修改，不用重置、覆盖或删除换取整洁状态。
- 不重写、删除或覆盖冻结机器证据；更正通过追加记录完成。

## 晋升硬门

晋升不是普通开发步骤，必须同时满足：

1. 用户明确授权本次晋升及目标目录；
2. 候选范围冻结，来源基线和候选文件身份明确；
3. 变更映射逐项列出候选源、成熟目标、操作和理由；
4. 必需验收项全部通过，没有通过删测试、缩小采集或放宽阈值换取 PASS；
5. 当前候选对应的机器证据和人工审查结论齐全；
6. NO-GO、跳过项、外部依赖和残余风险已处理或由用户明确接受；
7. 晋升前记录成熟基线状态并保留可恢复副本；晋升后复验结构、链接、入口、测试和内容边界；
8. 晋升只复制映射中获批内容，不复制缓存、临时结果或整个工作区。

候选工作区在晋升验收完成前不删除。

## 失败与回退

失败证据应保留并标为 FAIL、NO-GO、PARTIAL 或 UNKNOWN。回退必须绑定明确文件副本或备份，优先采用可审查的恢复操作，不直接覆盖不明来源的修改。

成熟基线漂移、错误晋升或证据与被测内容不一致时，停止后续晋升，记录差异并请求用户决定。
