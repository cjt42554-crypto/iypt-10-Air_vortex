> 审计角色：独立需求与发布审计，不参与 `src/`、`tests/`、`docs/` 的实现或修订。  
> 需求基线：`/home/cjt/竞赛物理研究四层通用框架与统一计算平台需求说明.md`（706 行）。  
> 审计对象：本仓库的 README、配置、理论/数值/实验文档、研究附件、源码、测试和最终运行证据。  
> 当前状态：**工作中快照，不是发布通过结论**。实现文件稳定后，必须重新逐项复核并用实际命令、返回码、归档哈希和 GUI 烟测证据替换“待执行”。

## 1. 审计原则与判定词

本审计不把“文档写了”“代码存在”“单元测试通过”“短算例稳定”“图像看起来合理”“两个后端数值接近”混为同一种证据。采用以下判定词：

| 判定 | 含义 |
|---|---|
| **满足** | 需求有实际可达实现，且与所需风险相称的验收证据已在本次发布中执行并保存 |
| **部分满足** | 需求只覆盖有限模型域、有限入口或部分功能；边界已清楚标注 |
| **未满足** | 需求缺少实现，或实现与需求的科学对象不一致 |
| **阻断** | 足以阻止“完整交付/可运行平台/定量预测已验证”等发布声明 |
| **待执行** | 代码或门禁可能存在，但尚无本次最终稳定版本上的运行证据 |
| **不适用** | 对本题确有明确物理理由；不能用“不适用”掩盖未实现 |

证据优先级固定为：需求原文 → 可达源码 → 测试内容 → 本次实际运行产物 → 文档声明。文档不得反向证明代码存在，测试名称不得代替其断言内容，质量/散度等被修正量不得只用修正后的残差证明。

## 2. 总体结论门槛

最终发布至少要同时区分三种结论：

1. **理论闭合**：给定完整输入后，模型在所声明研究区间内是否原则上唯一决定状态，包括触及、拓扑变化、接触线、夹断或分支切换；
2. **软件可运行**：统一 GUI/CLI 的双后端、暂停/继续/软停止、扫描、同条件比较、实验导入和归档是否真实可达；
3. **物理可预测**：数值离散是否确证，经验参数是否独立标定，预测是否经过完整运行/几何分组的冻结盲验。

当前代码有意把 Forward 标为降阶模型，把 `high_fidelity` 标为 H1/HF-preview，并否认其可定量预测贯通后气道或绝对临界转速。这种能力边界是正确的；但它也意味着在没有进一步理论闭合、数值确证和实验数据时，发布措辞只能是“可运行的研究与机制预览平台”，不能是“真实空气通道已被高保真模拟或定量验证”。

## 4. 当前快照已发现但尚未作最终判决的问题

以下问题在实现稳定前被记录为“需复核”，对应文件若随后修复，应在最终审计中写明复核结果，不保留过时指控。

1. **GUI 可达性**：审计快照中 `airvortex.gui.launch()` 延迟导入 `.app`，当时 `src/airvortex/gui/app.py` 尚不存在；若发布时仍然如此，`run_gui.sh` 和 `airvortex-gui` 均为阻断失败。
2. **测试框架/旧 schema**：快照中的 `tests/test_gui_model.py` 仍依赖 pytest 且断言旧配置结构，与 README 宣称“标准库 unittest、不需额外测试框架”冲突。
3. **H1 测试作用域错误**：快照中的时间步加密测试末尾引用另一测试方法内的 `positive/negative`，会导致 NameError；必须在最终稳定版全套运行中确认消失。
4. **H1 文档—代码界面重建不一致**：数值文档一度描述 Euclidean 距离重建，而代码默认调用守恒 CLS 压缩/扩散通量；最终只能保留与实际代码一致的算法说明。
5. **压力诊断缺口**：投影算子计算 `removed_rhs_mean`，H1 step/result 当时未保存它；数值文档却要求保存。最终须实现或降低声明。
6. **休眠求解器参数**：H1 直接 `splu` 路径当时不使用 `pressure_relative_tolerance` 和 `pressure_max_iterations`；Forward 的 `relative_tolerance` 也未见实际使用。GUI 若把它们作为有效求解器控制展示会误导用户。
7. **理论文档公式损坏**：快照曾出现控制字符导致 `\frac` 丢失、`\left`/`\simeq`/`\quad` 反斜杠缺失及标点拼写错误。最终必须通过控制字符和公式渲染检查。
8. **第一层范围**：M2 和 H1 都在官方细空气通道真正建立时停止定量物理声称。若 M0 仍未选择唯一拓扑/接触线闭合，则整项交付只能称“贯通前理论 + 贯通候选/结构研究”，不能称官方现象已有闭合预测。
9. **停止终态一度被标成完成**：GUI 快照中 runtime `CANCELLED` 一度被映射到 `RunState.COMPLETED`，状态栏因而显示“已完成”。GUI 实现者已报告改为独立 `CANCELLED`；最终必须对无结果取消、部分结果取消、扫描取消和暂停中取消逐支重验，不以修改通知代替证据。
10. **GUI 一度误述 H1 域高**：参数帮助曾称静液深即 H1 轴向计算域高，而后端实际用 `1.25×静液深`以容纳闭合气层。实现者已报告修改；最终需对 GUI、帮助、结果 metadata 和数值文档四处一致性重验。
11. **实验 metadata 不是严格 JSON**：`analysis/experiment.py` 快照使用普通 `json.loads`/默认 `json.dumps`，会接受重复键和 `NaN`/`Infinity`，也可导出非标准 JSON；这与 core 配置的严格门禁不一致。最终应复用 strict loader/dumper，并测试重复键、非有限数和往返。
12. **单位缺失可被伪装为可比**：`analysis/comparison.py::_unit_from_result` 快照在单位 metadata 缺失时返回通配字符串 `SI`。若两个结果都漏单位，异物理维度也可通过相等检查。最终应在缺单位时硬拒绝，或通过严格 observable schema 唯一定义单位。
13. **封存 provenance 未覆盖验收合同**：快照已记录配置哈希、环境与 runtime wall duration，但尚无精确命令、源码修订/源码树哈希、CPU 时间和峰值内存；而数值验收文档明确要求后两者。若发布前不补，`SW-05` 只能判部分满足。
14. **H1 文档与并发源码一度再次漂移**：数值文档曾声称 `removed_rhs_mean` 未存档、`pressure_relative_tolerance` 不生效；同时的后端已保存该诊断并将相对压力残差用作超限硬失败门禁。文档代理已确认将按稳定源码重写；最终必须重新逐字段对照。
